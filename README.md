# University Exam Design Patterns

## Описание на проекта

Проектът моделира процес по провеждане на контролно в университет чрез използване на основни шаблони за проектиране.

Сценарият описва университет, в който студентите пристигат по различни начини, системата разпознава техния тип и им дава подходяща задача. По време на контролното студентите могат да придобиват различни суперсили.

## Условие

Дойде денят на контролното.

Студентите пристигат в университета с притеснение и надежда.

Университетът е единствен и неповторим. В него контролното се провежда чрез специална система, която разпознава типа студент и му дава съответна задача.

Различните типове студенти са:

* вундеркинд;
* фитнес маниак;
* калитко.

Получените задачи са съответно:

* забавни;
* непонятни;
* лесни.

Студентите могат да придобият суперсили по време на контролното:

* свръхконцентрация;
* бързопис;
* телепатия.

Всеки студент използва различна стратегия, за да пристигне в университета:

* тичане с подскачане;
* телепортация;
* спане в автобус.

## Използвани шаблони за проектиране

В проекта са реализирани следните шаблони:

| Шаблон    | Реализация                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------ |
| Singleton | `University`                                                                                     |
| Factory   | `TaskFactory`                                                                                    |
| Decorator | `StudentPowerDecorator`, `SuperConcentration`, `FastWriting`, `Telepathy`                        |
| Strategy  | `ArrivalStrategy`, `RunningAndJumpingStrategy`, `TeleportationStrategy`, `SleepingInBusStrategy` |

---

## Singleton — University

Класът `University` е реализиран като Singleton, защото според условието университетът е единствен и неповторим.

Това означава, че не може да се създават множество обекти от типа `University`.

Вместо това се използва:

```java
University university = University.getInstance();
```

Конструкторът на класа е `private`, а достъпът до единствената инстанция става чрез статичния метод `getInstance()`.

---

## Factory — TaskFactory

Factory шаблонът е използван за създаване на задачи според типа студент.

Класът `TaskFactory` приема `StudentType` и връща подходяща задача:

| Тип студент      | Създадена задача |
| ---------------- | ---------------- |
| `WUNDERKIND`     | `FunTask`        |
| `FITNESS_MANIAC` | `ConfusingTask`  |
| `LUCKY`          | `EasyTask`       |

Така логиката за създаване на задачи е отделена от главната програма.

---

## Decorator — Student Powers

Decorator шаблонът е използван за добавяне на суперсили към студентите.

Основният обект е `Student`, който имплементира интерфейса `ExamParticipant`.

Суперсилите също имплементират `ExamParticipant` чрез базовия декоратор `StudentPowerDecorator`.

Това позволява студентът да бъде разширяван с различни способности, без да се променя класът `Student`.

Пример:

```java
ExamParticipant poweredStudent = new SuperConcentration(
        new FastWriting(student)
);
```

Така студентът получава едновременно бързопис и свръхконцентрация.

---

## Strategy — Arrival Strategy

Strategy шаблонът е използван за различните начини на пристигане в университета.

Всеки студент има поле от тип `ArrivalStrategy`.

Конкретните стратегии са:

* `RunningAndJumpingStrategy`;
* `TeleportationStrategy`;
* `SleepingInBusStrategy`.

Пример:

```java
Student student = new Student(
        "Иван",
        StudentType.WUNDERKIND,
        new TeleportationStrategy()
);
```

Така начинът на пристигане може да се сменя, без да се променя класът `Student`.

## Заключение

Проектът демонстрира използването на четири основни шаблона за проектиране:

* Singleton — за единствен университет;
* Factory — за създаване на задачи;
* Decorator — за добавяне на суперсили;
* Strategy — за различни начини на пристигане.

Чрез тези шаблони кодът е по-добре структуриран, по-лесен за разширяване и по-ясно разделен по отговорности.
